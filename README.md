**成果・実績**

##### 開発体制の最適化

- モジュラーモノリス設計を採用し、モジュール単位でタスクを分割することで、多くのメンバーにタスクを割り当て、並行開発しやすい体制を構築

##### 品質保証の仕組み化

- ESLint、 ESLint Stylisticによる厳格なコーディング規約の設定により、開発者がコーディング規約に向ける認知負荷を抑えながら、コード品質を担保。レビュー時に規約違反を指摘する必要がなくなり、やりとりに必要な時間やレビュー観点を削減  
- ブランチルール、コミットメッセージ規約等も機械的にチェックする仕組みを導入  
- lefthookを用いたgit hooksの整備により、コーディング規約のチェックなしでコミットやプッシュされることを防止

##### テスト戦略の標準化

- テストカバレッジ95%以上をPR作成・更新時にCIで自動チェックし、基準を満たさない場合はマージをブロックする仕組みを構築。手元で実行して確認する必要がなくなり、最低限のテストが書かれているかの確認コストを削減  
- テストコードの存在により、作業者とレビュアー間で仕様の相違や漏れを確認しやすい状態を実現  
- 担当外の箇所への影響範囲がカバレッジレポートで可視化され、認知負荷を下げながら品質を担保しやすい状態へ改善  
- 上記のテスト戦略とコーディング規約の自動化を合わせ、1件あたり1時間以上を要していたコードレビューを30分以内に短縮。1日4時間以上レビューに追われる日もあった負荷を解消

##### CI/CDパイプラインの構築

- GitHub Actionsを活用し、IaC、ECSデプロイ、ER図更新を自動化  
- デプロイの自動化によりデプロイを実行する環境差異を排除し、安全かつ迅速なリリースフローを確立

##### 型安全性の向上

- バックエンドのコードからOpenAPI仕様を自動生成し、フロントエンドの型定義を自動生成  
- API変更時の影響範囲の可視化と、型安全なAPI通信を実現し、開発体験が向上

## 自己PR

### 【チームの生産性を仕組みで底上げする開発体制づくり】

直近のリードエンジニアとしての業務では、個人のスキルや注意力に依存せず、ツールやCIによって品質を機械的に担保する開発体制の構築に注力しました。コーディング規約・テストカバレッジ・デプロイフローを自動化することで、レビュアーや実装者の認知負荷を下げ、本質的な設計や仕様の議論に時間を使える環境を整えました。チーム全体の開発体験を改善することが、結果的にプロダクトの品質と速度の両立につながると考えています。 

### 【フロントエンドからインフラまで一貫して担える技術力】

受託開発で6年間、アパレル、公共交通、医療、福祉など多様な業界の案件に携わってきました。フロントエンド、バックエンド、AWSによるインフラ構築、IaC、CI/CDまで一貫して対応できることを強みとしており、その技術力を土台にドメインの要件を構造化し、システムとして成立する形に設計、ゼロから動くシステムを作り上げてきました。

### 【今後について】

受託開発の6年間では、業界ごとに異なるドメインをゼロから理解し、限られた期間でシステムとして成立するように構造化する力や、フロントエンドからインフラまで一貫して立ち上げられる技術の幅を培うことができました。一方で、受託開発では、限られた予算とスケジュールの中で要件を満たすことが最優先となるため、パフォーマンス最適化やアーキテクチャの中長期的な改善、モニタリングに基づくボトルネックの分析と改善といった領域に深く踏み込む機会は多くありませんでした。今後は自社サービスの開発に携わり、これまで掘り下げきれなかったこうした技術領域に腰を据えて取り組みたいと考えています。フロントエンドからインフラまで一貫して対応できる幅広さと、品質を仕組みで担保する開発体制づくりの経験を土台に、サービスの信頼性と開発生産性の両面から貢献していきたいです。
